# lsn 的小站

原生 HTML / CSS / JavaScript 的个人博客，适配手机和平板，没有数据库和构建步骤。前端部署到 GitHub Pages，记录通过 GitHub Contents API 自动保存到仓库 JSON。

## 本地预览

在项目根目录运行 `python3 -m http.server 18765 --bind 127.0.0.1`，打开 http://127.0.0.1:18765 。使用 HTTP/HTTPS 访问，不支持 file://。

## 自动保存

页面从 `js/github-credentials.js` 读取配置，自动解密令牌并载入仓库内容。界面没有“数据与文件”页面、凭据输入、手动提交、目录绑定或 JSON 导入导出。

新增、编辑记录并点击编辑弹窗的“保存”、删除记录、切换完成状态、发送消息后，立即发起请求。尚未确认的表单草稿不会提交，昵称仍仅保存在浏览器。

请求按顺序上传；上传期间的连续编辑会合并为下一次提交。每次读取最新文件，按记录 ID 合并其他用户对不同记录的修改；同一条记录有不同修改时停止保存，不覆盖远端。

页脚显示保存状态。网络或服务端临时错误自动重试，最多三次；失败后显示“重试保存”。未上传的修改保留在页面内存，关闭前会提醒。无法自动合并的同记录冲突需自行复制待保存文本作备份，再刷新载入远端版本后重新编辑。

这里指页面记录编辑后的自动提交，无法监控电脑上手工修改的项目文件或照片；这些文件仍需要 Git 提交。每次成功上传会生成 commit，频繁操作可能触发 API 限流。

## 仓库和部署

默认目标：`Sjim/sjim.github.io`，`master` 分支，`data/content.json`。连接目标从凭据配置中的 repository 读取；分支和数据文件须已存在。令牌需具备仓库 Contents 读写权限，过期或撤销后需更新配置重新部署。

启动连接失败会尝试匿名 API，再退回已部署 JSON，页脚提示错误。可重试连接并保留当前编辑。API 保存成功后，GitHub Pages 仍需完成部署才能更新静态文件，请配置相应分支或部署 workflow。

**配置包含明文密码和令牌密文，访客可以还原令牌并获得其权限。这只是混淆，没有保密性。** 公开 JSON 和 commit 历史不适合私密记录；撤销令牌需要在 GitHub 操作。

## 页面与照片

五个 Tab：博客、琴谱、备忘录日志、对话、一周年时间轴。琴谱复用 `tableData.json` 和 `photo/` 图片。

时间轴支持照片路径、HTTP/HTTPS 链接或图片上传。推荐将照片单独提交到 `photo/` 后引用相对路径。网页上传图片会嵌入 JSON，单张限 5 MB；整个 JSON 的 GitHub 保存上限为 1 MB，超限时需改成图片路径或链接。填写路径不会上传对应图片文件。

对话消息发送后自动保存，同浏览器标签页实时同步新消息；接收标签页不重复提交。不同设备没有实时推送，需要刷新读取历史。

## 验证

`node --test tests/*.test.mjs`

模拟 API 测试覆盖编码、凭据解密、浏览器 fetch 上下文、自动保存队列、合并、冲突及重试，不向真实仓库写入测试数据。
