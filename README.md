# lsn 的小站

原生 HTML / CSS / JavaScript 的个人博客，适配手机和平板，没有数据库和构建步骤。前端部署到 GitHub Pages；内容通过 GitHub Contents API 保存到仓库 JSON 文件。

## 本地预览

在项目根目录运行：

```sh
python3 -m http.server 18765 --bind 127.0.0.1
```

打开 http://127.0.0.1:18765 。请通过 HTTP/HTTPS 访问，file:// 模式无法读取 JSON。

## 页面

- 博客：新增、编辑、删除、搜索文章。
- 琴谱：复用 `tableData.json` 和 `photo/` 图片，支持搜索及完整琴谱查看。
- 日志：备忘录增删改查及完成状态。
- 对话：首次进入设置昵称，仅昵称保存到 localStorage；同浏览器标签页通过 BroadcastChannel 同步新消息。消息历史可随 JSON 提交到 GitHub。
- 一周年：按年月排序的照片文字时间轴，支持增删改查。照片可以使用项目图片路径、HTTP/HTTPS 图片链接或上传图片。

## GitHub 文件保存

默认配置位于 `js/github-store.js`：

- 仓库：`Sjim/sjim.github.io`
- 分支：`master`
- 文件：`data/content.json`

部署前，需要把本次代码及初始 `data/content.json` 提交到上述分支。连接要求该文件已经存在，不会自动创建缺失文件或分支。仓库或分支不同，可以在连接表单修改；网站启动时的默认读取目标需同步修改 `defaultRepository`。

### 自动连接与使用流程

凭据读取自 `js/github-credentials.js`。页面启动时自动解密配置中的令牌并连接仓库；界面不再提供令牌、密码、仓库或分支输入，也不再提供配置生成入口。请直接维护已有配置文件，令牌需要目标仓库的 **Contents: Read and write** 权限。

1. 将代码、配置文件和 `data/content.json` 提交并部署。
2. 打开页面后自动读取仓库最新内容。
3. 编辑记录后，点击页脚“数据与文件”中的 **提交到 GitHub** 保存。
4. 版本冲突时，先导出 JSON 备份，再点击 **重新载入仓库内容**，整理修改后重新提交。重新载入会询问是否替换未提交内容。

令牌撤销或过期后需更新配置文件并重新部署。连接失败时保留只读内容，检查配置或网络后可重新载入；不再要求在页面输入凭据。提交期间的新编辑会保持待提交状态。GitHub Pages 部署需要监听保存分支；API 提交成功不等于部署已完成。

**配置包含明文密码和令牌密文，任何访客均可还原令牌并获得其权限。此方案只是混淆，不提供令牌保密性。** 将配置的 `enabled` 改为 false 可关闭自动连接，但撤销已公开令牌必须在 GitHub 操作。

启动时优先使用配置令牌读取仓库；失败时尝试匿名 API，再退回已部署的 JSON。API 限流或网络失败时可能看到部署版本。

### 照片与大小

GitHub 读取逻辑要求 JSON 不超过 **1 MB**。因此推荐把照片文件上传到仓库 `photo/` 目录，在时间轴填写 `photo/anniversary/example.jpg`，或使用外部图片链接。照片路径只是引用，不会通过 JSON 提交自动上传对应图片。

页面上传的图片会作为 data URL 嵌入 JSON，本地模式单张限 5 MB；GitHub 模式提交时对整个 JSON 检查 1 MB 上限，超过时会拒绝并提示。请将大图片改成文件路径或链接。

公开仓库的 JSON 和 commit 历史对外可见，不适合保存私密备忘录或敏感信息。开启明文密码自动连接后，访客可以使用公开配置还原的令牌提交。

## 本地文件备份

“数据与文件”中仍保留：

- **导出 JSON**：下载全部当前数据。可作备份，也可手动替换项目 `data/content.json` 后提交。
- **导入 JSON**：确认后替换全部当前记录。自动连接成功后导入备份，最后提交；导入本身不会自动发起 GitHub 提交。
- **绑定项目目录**：自动连接未启用或失败时，在支持 File System Access API 的 Chromium 浏览器，通过 HTTPS 或 localhost 选择项目根目录。每次编辑自动写入本机项目的 `data/content.json`。重开页面后需重新绑定。

除昵称外，未提交且未保存到本地目录的编辑仅存在页面内存中，离开前请保存或导出。

## 公共聊天的边界

GitHub API 适合低频内容发布，当前对话页仍不提供跨设备实时公共聊天。历史消息随文件提交；其他访客刷新页面可读取已提交的历史，但启用公开自动连接配置后访客可以手动提交消息，但仍无跨设备实时推送。不同标签页的新消息实时同步限于同一浏览器、同一站点。

要开放匿名公共聊天，需要一个共享服务来鉴权、接收消息及推送更新，不能把有仓库写权限的令牌暴露给所有访客。
